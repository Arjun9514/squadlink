# SquadLink – Frontend Module (`frontend`)

Interactive web interface for **SquadLink**, a vector-driven player matchmaking and gameplay telemetry platform. Built with Python and Streamlit, it integrates relational database routines from MySQL (`sql/`) and document-oriented telemetry and activity feeds from MongoDB (`nosql/`).

---

## Features Overview

The frontend is divided into 8 navigation tabs:

1. **Lobbies (`frontend/views/lobbies.py`)**
   - Browse and filter matchmaking lobbies by Game and Status (`open`, `full`, `in_progress`, `completed`).
   - Real-time slot utilization tracking via stored function `fn_lobby_size(LobbyID)`.
   - Inspect full squad participant rosters with Squad Roles and Ready Status indicators.
   - Host controls: Start Match (`in_progress`) and Close Lobby via stored procedure `sp_close_lobby(p_lobby)` (records `LOBBY_COMPLETED` audit log).
   - Create new matchmaking lobbies with automatic host assignment.

2. **Join a Lobby (`frontend/views/lobbies.py`)**
   - Transactional lobby entry powered by `sp_join_lobby(p_lobby, p_user, p_role)`.
   - Enforces trigger `trg_part_bi` (restricting joining to `open` lobbies and capacity `< 5`).
   - Automatically marks status as `full` via trigger `trg_part_ai` when the 5th participant enters.
   - Records `LOBBY_JOINED` activity events in MongoDB.

3. **Find a Match (`frontend/views/matchmaking.py`)**
   - Vector-driven teammate recommendation powered by `sp_find_match(p_lobby, p_min_rep)`.
   - Computes 3D Euclidean playstyle vector distance using stored function `fn_playstyle_dist`:
     $$d = \sqrt{(A_1 - A_2)^2 + (T_1 - T_2)^2 + (O_1 - O_2)^2}$$
   - Filters candidate players by Minimum Reputation Score.
   - Compares Host and Candidate 3D playstyle vectors (`Aggression`, `Teamwork`, `Objective Focus`).
   - One-click lobby recruitment action.

4. **Ratings (`frontend/views/ratings.py`)**
   - Post-match player feedback submission (`Score 1–5`).
   - Trigger `trg_feedback_bi` validates that players cannot review themselves and enforces score boundaries.
   - Trigger `trg_feedback_ai` automatically triggers `fn_avg_rating(NEW.ReviewedUserID)` and recalculates `player_profile.ReputationScore`.
   - Community reputation leaderboard and recent feedback history.

5. **Players (`frontend/views/players.py`)**
   - Directory of registered player profiles across all games.
   - 3D Playstyle Vector visualizer with dimension breakdown.
   - Telemetry JSON metadata viewer (`kd`, `win_rate`, `matches`, `gpm`, `goals`).
   - Social connections network (`friend`, `follow`, `block`) with self-connection constraint enforcement.
   - Interactive 3D playstyle vector tuner.

6. **Gameplay Telemetry (`frontend/views/telemetry.py`)**
   - Match statistics recording form storing sessions in MongoDB collection `game_sessions`.
   - Captures duration, outcome, kills, deaths, assists, accuracy %, damage dealt, playstyle sliders, and notable events.
   - **Player Performance Summary**: Aggregated metrics computed via MongoDB aggregation pipeline (`matches`, `wins`, `kd`, `win_rate`, `avg_accuracy`, total playtime).
   - Match history table with filters and kills distribution bar chart.

7. **Activity Feed (`frontend/views/activity_feed.py`)**
   - Chronological event timeline streaming from MongoDB collection `player_activity`.
   - Tracks platform actions: `MATCH_RECORDED`, `LOBBY_CREATED`, `LOBBY_JOINED`, `LOBBY_COMPLETED`, `FEEDBACK_SUBMITTED`, `ROLE_CHANGED`, and `PROFILE_UPDATED`.
   - Filter by player and action type.

8. **Admin (`frontend/views/admin.py`)**
   - **Security Audit Logs**: View audit trail generated by trigger `trg_user_au` (`ROLE_CHANGE`, `PASSWORD_CHANGE`) and `sp_close_lobby`.
   - **User Role Management**: Update user roles (`player`, `moderator`, `admin`) with live trigger audit logging.
   - **Analytical Nested Queries**:
     - *Nested Query 1*: Players whose `ReputationScore` is strictly above the platform average.
     - *Nested Query 2*: Valorant lobby participants with 5-star ratings.
   - **Demo Reset Utility**: Runs `sql/reset_demo.sql` commands to restore initial clean baseline state.

---

## Dual-Mode Architecture

SquadLink frontend supports two operational modes:

1. **Live Database Mode**: Connects directly to MySQL 8.0 on `localhost:3306` (or remote host) and MongoDB on `localhost:27017`. All stored procedures, triggers, and functions execute in the database engines.
2. **Demo Mode (In-Memory Fallback)**: If MySQL or MongoDB is offline or credentials are not yet configured, the application falls back to an in-memory replica preloaded with baseline seed data from `sql/DML.sql`. All procedure logic, triggers, vector calculations, and aggregations are faithfully executed.

## Getting Started

### 1. Prerequisites

Ensure Python 3.10+ is installed.

### 2. Install Dependencies

```bash
pip install -r frontend/requirements.txt
```

### 3. Run the Application

You can run the application from the repository root:

```bash
streamlit run app.py
```

Or from inside the `frontend/` directory:

```bash
cd frontend
streamlit run app.py
```

### 4. Configuration (Optional)

Override connection strings via environment variables if using custom database credentials or MongoDB Atlas:

```bash
# MySQL
export MYSQL_HOST=localhost
export MYSQL_PORT=3306
export MYSQL_USER=root
export MYSQL_PASSWORD=your_password
export MYSQL_DATABASE=squadlink

# MongoDB
export SQUADLINK_MONGO_URI=mongodb://localhost:27017
export SQUADLINK_MONGO_DB=squadlink_nosql
```
